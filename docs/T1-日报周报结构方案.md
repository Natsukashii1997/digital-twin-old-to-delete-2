## 1. 摸底结论（只列数字，原文见证据目录）

能用的历史只有 07-14 以后这一代（62 篇），更早的格式换过两次，而且多半是「无记录」。下面的数字都按这 62 篇算。

1. **行动没有跨天记忆**：未完成的行动 373 条，其中 73% 之后再也没出现，后来被写成「已完成」的只有 2 条。晨报只能写「日报未见关闭」，「挂起满 4 周」也算不出来。
2. **截止大多没法算**：392 条行动和阻塞里，写成绝对日期的只有 28%；38% 是空的或「近期 / 待定 / 持续」，22% 是「明天 / 本周 / 月底」这类相对时间。
3. **同一件事写 4～9 遍**：沟通记录一段就占全文 42%，结论又在事项、决策、洞察、行动、建议里各写一遍；全文中位数 4483 字。
4. **没有项目归属**：行动没有项目列；个人项目的开发进展完全不在日报里。
5. **「阻塞」名不副实**：常年挂着的「阻塞」其实是自己没处置；日报和周报对挂起周数的计数还对不上。
6. **方法论、洞察没人用**：方法论 67 条里 61 条一直是「待确认」。
7. **格式脆**：表头多种写法；10-26 起飞书表格转换后，晨报脚本读第四段读出 0 行；有一天的日报没被识别并进了另一天；周报 4 个月里换了 5 套格式。
8. **分级**：日报写进了私人话题，周报模块五（对常浩的画像）属于受限内容，都放在飞书租户的文档里。

## 2. 设计原则

1. **一件事一个编号，跨天带着走。** 日报只写「今天变了什么」，加一份「还开着什么」的台账；事情要么关闭（写依据），要么留在台账里，不允许无声消失。
2. **机器要读的字段写成固定格式的单行，不用表格。** 用 `｜` 分隔「键：值」，截止一律写成 `YYYY-MM-DD` 或「无」，避开飞书表格转换的问题。
3. **每件事只在一处展开。** 对话不再逐人罗列，改成挂在事项下的一行「依据」。
4. **日报只写工作。** 内容按内部级把关：私人话题不写；画像、方法论移到 Vault 收件箱（F3.3、F7）。
5. **每段都要有下游。** 说不出给谁用的段落就删掉。

## 3. 推荐方案 A：台账式

### 3.1 日报

标题格式不变（`📅 2026-10-23（周五）`），牛马之家照旧按标题切分。每天一个独立标题，不和别的日期合并。

```
## 📅 2026-10-23（周五）
> 今天一句话：……（≤40 字）

### 一、今天的变化
（按项目分组；🆕 新增 ⏩ 推进 ✅ 关闭 ✖️ 放弃 📣 消息）
- 🆕 [A1023-1] 事项｜负责：常浩｜截止：2026-10-26｜状态：进行中
  依据：群聊「xx」15:58 某某确认……；16:27 常浩承诺……
- ✅ [A1022-2] 事项｜关闭依据：私聊 某某 09:48 确认已导出

### 二、还开着的事（N 件）
⏰ 有截止（按截止排序）
- [A1022-3] 事项｜项目｜负责｜截止：2026-10-22｜已过期 1 天｜开 2 天｜最后动静：10/22 18:19
📌 没截止（开满 3 天的标 ❓，下一份日报问要不要定日期）
🧊 挂起（满 14 天没动静）
- [A0824-1] 事项｜首次：2026-08-24｜挂起约 9 周｜处置选项：继续（定日期）／顺延到某日／放弃

### 三、卡点
- ⛔ [A…] 卡在：等谁 / 等什么｜从：日期｜连续：N 份｜建议：……
（只放等外部的；自己没动的进「挂起」，不算阻塞）

### 四、今天的决定
- [D-20261023-1] 选了……｜因为……｜没选……｜项目｜依据

### 五、项目进展（自动）
- 牛马之家：提交 52｜主题一句话
- 没动静：agent-kit、数字分身

### 六、下个工作日先推（≤3）
1. [A…] 短名 — 为什么（今天到期 / 已过期 N 天 / 被追问）｜下一步：……｜可派：Claude / Codex（适合才写）

---
来源与覆盖：私聊 N 人｜群聊 N 个｜会议 N 场（跳过 N：永久排除）｜日程 N｜任务 N｜妙记 N｜仓库 N｜略过个人话题 N 段｜读取失败：无
```

各段规则：

| 段 | 写什么 | 不写什么 |
|---|---|---|
| 一句话 | 当天最重要的推进或决定 | 情绪、评价 |
| 一、今天的变化 | 有动作或结论的事；每条带编号和依据（谁、几点、关键原话 ≤20 字） | 没有结论的寒暄；没有实质发言的会议 |
| 二、还开着 | 全部未关闭事项，前一篇的台账 + 今天的变化 | 已关闭的（关闭当天在「一」里出现一次就够） |
| 三、卡点 | 等外部超过 2 个工作日，或明确被卡住的 | 自己拖着的（进挂起） |
| 四、决定 | 常浩拍板或参与拍板的；沿用 `D-日期-序号` | AI 自己的抽象「洞察」 |
| 五、项目进展 | 项目名册里的仓库，每个项目一行 | 提交清单（要细节就在私聊里现查） |
| 六、先推 | 按晨报的同一套排序规则，替下个工作日挑 ≤3 件 | 新事项（只能引用二、三里已有的编号） |
| 覆盖行 | 每个来源读了多少、哪个失败了 | — |

取消的段：沟通记录（变成「依据」行）、洞察、方法论（每周作为候选进 Vault 收件箱）、AI 建议（变成「先推」+ 挂起的处置选项）。
样稿按 10-23 改写后，字数是原文的四成（6930 → 2939 字，已含 16 件台账）。

### 3.2 周报

标题格式不变（`第43周 2026.43（2026.10.19 - 10.23）`）。

```
## 第43周 2026.43（2026.10.19 - 10.23）
```

### 3.3 字段约定

| 字段 | 约定 |
|---|---|
| 行动编号 | `A` + 首次出现的月日 + `-` + 当日序号，如 `A1023-1`；从旧日报迁移过来的事项，按首次出现的日期编号 |
| 决定编号 | 沿用 `D-YYYYMMDD-n` |
| 状态 | 进行中／等待（等别人）／阻塞／挂起／已完成／已放弃，六选一 |
| 截止 | `YYYY-MM-DD` 或「无」；相对时间在写入时就换算成日期，原话可以写在括号里；不猜日期 |
| 项目 | 固定词表：项目名册里的个人项目 + 工作线（双11、管培生、中台、稳分、国课、新人入职……）；词表放在本仓库，常浩可以改 |
| 依据 | 来源类型 + 对象 + 时间 + 关键原话（≤20 字） |
| 开了几天 / 最后动静 | 从台账继承，每天重算 |

## 6. 备选方案 B：保留六段，只把字段规范化
